One engine, three surfaces

Every A-Coder surface runs the same agent engine: the same tools, the same session format, the same provider configuration, the same extension model. Configure once — in ~/.a-coder/agent/ — and every surface picks it up.

A-Coder CLI

The engine itself. Interactive terminal agent, scriptable in print/JSON/RPC modes.

A-Coder IDE

VS Code-based editor with the agent built into the sidebar and inline edits.

A-Coder Desktop

Native Tauri app wrapping the CLI engine — workspaces, session tree, voice.

02

Getting started

A-Coder CLI

One-line install (self-contained binary), then run a-coder-cli in any project:

curl -sSf https://raw.githubusercontent.com/hamishfromatech/a-coder-cli/feat/desktop-unified-release/install-a-coder.sh | bash

Authenticate with an API key or an existing subscription:

export ANTHROPIC_API_KEY=sk-ant-...
a-coder-cli            # or: /login to use Claude Pro/Max, ChatGPT, Copilot

A-Coder IDE

Installer script (macOS/Linux) — Windows uses install.ps1:

curl -fsSL https://raw.githubusercontent.com/hamishfromatech/A-Coder/main/install.sh | bash

A-Coder Desktop

Requires the CLI on your PATH (Node 22+). Grab an installer from GitHub Releases — or launch it straight from the terminal:

a-coder-cli --desktop

Set A_CODER_DESKTOP_BINARY to point at a custom build, or A_CODER_DESKTOP_DEV=1 to run via tauri dev from a checkout.

A-Coder CLI

The interactive tour

From top to bottom:

  • ▸Startup header — active shortcuts (/hotkeys for all), loaded AGENTS.md files, prompt templates, skills, and extensions.
  • ▸Messages — your prompts, assistant replies, tool calls with glyph + stats result cards, notices, and extension UI.
  • ▸Editor — where you type; the border color indicates the thinking level.
  • ▸Status rail & footer — background-agent status, working directory, token/cache usage, cost, context left, current model.

Shortcuts & the message queue

Commonly used shortcuts (full list via /hotkeys, customizable in ~/.a-coder/agent/keybindings.json):

Ctrl+LModel selector
Ctrl+P / Shift+Ctrl+PCycle scoped models forward / back
Shift+TabCycle thinking level
Ctrl+OCollapse / expand tool output
Ctrl+TCollapse / expand thinking blocks
Escape ×2Open the session tree

Submit messages while the agent is still working: Enter queues a steering message (delivered after the current tool loop), Alt+Enter queues a follow-up (delivered when all work finishes), Alt+Up pulls queued messages back into the editor. Delivery behavior is configurable in /settings.

Sessions & branching

Sessions are JSONL trees — every entry has an id and parentId, so branching happens in place inside a single file. Auto-saved to ~/.a-coder/agent/sessions/ by working directory.

a-coder-cli -c                  # continue most recent session
a-coder-cli -r                  # browse and select past sessions
a-coder-cli --no-session        # ephemeral mode (don't save)
a-coder-cli --name "my task"    # named session
a-coder-cli --fork <id>         # fork a session into a new file

Compaction keeps long sessions inside the context window: manual via /compact [instructions], or automatic by default (proactive near the limit, recover-and-retry on overflow). Compaction is lossy — the full history stays in the JSONL file, revisit anything with /tree.

Settings & project trust

~/.a-coder/agent/settings.jsonGlobal — all projects
.pi/settings.jsonProject — overrides global

A-Coder asks before trusting a project folder with local settings, resources, or skills — project-local extensions and settings only load after you trust it. Decisions persist to ~/.a-coder/agent/trust.json (or use --approve / --no-approve per run). Non-interactive modes fall back to defaultProjectTrust in global settings.

Context files

At startup the agent loads AGENTS.md (or CLAUDE.md) from the global directory, parent directories, and the current directory — all matching files are concatenated. Disable with --no-context-files.

Replace the default system prompt with .pi/SYSTEM.md (project) or ~/.a-coder/agent/SYSTEM.md (global); append without replacing via APPEND_SYSTEM.md.

Customization

Prompt templates

Reusable prompts as Markdown with {{placeholders}}. Live in ~/.a-coder/agent/prompts/ or .a-coder/prompts/; expand by typing /name.

Skills

On-demand capability packages following the Agent Skills standard — a SKILL.md the agent loads automatically when relevant, or on demand via /skill:name. Live in ~/.a-coder/agent/skills/, .a-coder/skills/, or .agents/skills/.

Extensions

TypeScript modules with full access to the runtime — custom tools, commands, keybindings, event handlers, UI components, providers, MCP integration, sub-agents, sandboxing:

export default function (pi: ExtensionAPI) {
	pi.registerTool({ name: "deploy", ... });
	pi.registerCommand("stats", { ... });
	pi.on("tool_call", async (event, ctx) => { ... });
}

Live in ~/.a-coder/agent/extensions/, .a-coder/extensions/, or shared as packages. Load one-off with -e ./my-ext.ts.

Themes & packages

Themes hot-reload — edit the active theme file and changes apply instantly. Share any of the above as packages: a-coder-cli install <source>, a-coder-cli update --all, a-coder-cli list.

CLI reference

a-coder-cli [options] [@files...] [messages...]

Modes

(default)Interactive mode
-p, --printPrint response and exit; also reads piped stdin
--mode jsonEmit all events as JSON lines
--mode rpcRPC mode for process integration (what Desktop speaks)

Model, session & tool options

--provider <name>anthropic, openai, google, …
--model <pattern>Pattern or ID — openai/gpt-4o, sonnet:high
--thinking <level>off · minimal · low · medium · high · xhigh
--models <patterns>Comma-separated patterns for Ctrl+P cycling
--list-models [search]List available models
-c / -rContinue most recent / browse sessions
--session <path|id>Use a specific session file or partial UUID
--tools / --exclude-toolsAllowlist / disable tools — built-ins: read, bash, edit, write, grep, find, ls
-e <source>Load an extension from path, npm, or git (repeatable)
--offlineDisable all startup network operations

Examples

# Interactive with an initial prompt
a-coder-cli "List all .ts files in src/"

# One-shot, piped stdin
cat README.md | a-coder-cli -p "Summarize this text"

# Different model, provider prefix optional
a-coder-cli --model openai/gpt-4o "Help me refactor"

# Read-only review
a-coder-cli --tools read,grep,find,ls -p "Review the code"

# Attach files with @
a-coder-cli -p @screenshot.png "What's in this image?"

Files prefixed with @ are attached to the message — text, code, or images.

Key features

Semantic context

Fast codebase search, paginated reading for large files, directory-tree awareness, symbol outlining — the assistant sees what you see and more.

Code application that actually works

Exact-match edits with clear error messages and uniqueness enforcement, Morph Fast Apply for high-speed application, and smart diff previews before anything lands.

Context management

TOON compression cuts tool-output tokens 30–70%; rolling windows and intelligent summarization keep long conversations coherent.

Autocomplete & quick edit

Inline FIM completion, Ctrl+K inline edits, vision support (drag images into chat), and multiple parallel threads.

Zero-friction migration

One click imports settings, keybindings, and extensions from VS Code, Cursor, or Windsurf.

Git integration

AI commit-message generation, repo tools (clone, pull, push, branch), and semantic search across git history.

Model Context Protocol

All three surfaces are MCP-native. Configure servers once and the agent discovers their tools automatically — internal APIs, knowledge bases, custom workflows.

  • ▸Hot reload — /reload picks up new or changed MCP servers, skills, and system prompts mid-session.
  • ▸Uniform rendering — MCP tool results render exactly like built-in tools: glyph, stats headline, expandable preview.
  • ▸Or build your own bridge — extensions can integrate MCP servers directly for full control.

Privacy

  • ▸Direct-to-provider — messages go straight from your machine to the provider. No middleman, no proxy.
  • ▸Zero retention — nothing stored, nothing trained on.
  • ▸Granular control — approve edits, terminals, and MCP tools individually; auto-approval is per tool category.
  • ▸Fully local — run entirely on Ollama, LM Studio, vLLM, or llama.cpp with --offline to disable all network extras.

Telemetry is opt-in and anonymous (no prompt content, paths, or identifiers beyond a random UUID) — disable with enableAnalytics: false or A_CODER_CLI_ANALYTICS=0. Update checks can be disabled separately with A_CODER_CLI_SKIP_VERSION_CHECK=1.
